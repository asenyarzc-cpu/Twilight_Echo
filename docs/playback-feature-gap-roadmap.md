# Twilight Echo 播放能力缺口与路线图

> 审计日期：2026-08-31  
> 范围：播放内核、输出设备、DSP、DSD、队列、长音频、投送和发布验证。  
> 本文只记录相对于 Twilight Echo「本地收藏 + 流媒体探索 + HiFi 桌面播放器」定位仍有价值的缺口，不追求枚举所有音乐软件曾经出现过的功能。

## 1. 结论

Twilight Echo 已经完成常规播放器和大部分发烧播放能力。剩余工作不应再以“增加功能名”为主，而应分为四类：

1. **产品声明必须与实现一致**：当前没有 CUDA 实现，不能把 CUDA 加速列为已支持能力。
2. **真实硬件闭环**：ASIO、WASAPI Exclusive、DoP、Native DSD、SACD ISO、CoreAudio Hog 和 ALSA `hw:` 仍需要可追溯的真机证据。
3. **设备与格式切换稳定性**：包括 ASIO 进程隔离、驱动 quirk、DSD 降速率、DoP 静音过渡、异格式连续播放和完整设备档案。
4. **外围播放体验**：包括章节、智能静音、AirPlay、多房间同步、远程队列管理、离线播客和响度标签生成。

本文共登记 **29 项**：P0 7 项、P1 13 项、P2 9 项。其中部分属于“已有基础但未闭环”，不能描述为从零缺失。

## 2. 状态与优先级

### 2.1 状态

| 状态     | 含义                                             |
| -------- | ------------------------------------------------ |
| 未实现   | 仓库中没有对应运行路径或公共能力                 |
| 部分实现 | 已有基础能力，但缺少关键行为、产品入口或完整验收 |
| 未验证   | 代码存在，但缺少目标平台或真实设备证据           |
| 平台限制 | 操作系统或协议本身不提供该路径，不应作为代码缺陷 |
| 可选扩展 | 有价值，但不属于播放器成为可靠主力机的前置条件   |

### 2.2 优先级

| 优先级 | 判定标准                                                  |
| ------ | --------------------------------------------------------- |
| P0     | 影响宣传真实性、设备安全、爆音/失锁、崩溃隔离或发布可信度 |
| P1     | 明显改善主力播放体验，且与当前架构和产品定位直接相关      |
| P2     | 面向特定设备、内容类型或生态的进阶能力                    |

## 3. 已有能力基线

下列能力已经存在，不再列为缺口：

- Native queue、无缝预加载、交叉淡化、顺序/列表循环/单曲循环/随机/心动模式。
- 变速不变调、原生 A-B 循环、睡眠定时、长音频续播、手动书签和播客单集进度。
- ReplayGain Track/Album、R128 标签读取、离线 Loudnorm、True Peak、软件音量与 bit-perfect 诊断。
- 图形/参数/动态均衡器、卷积、Crossfeed、声道矩阵、Bass Management、压缩、多段压缩、立体声场、响度轮廓、True Peak Limiter、VST3。
- REW、Equalizer APO、AutoEq、OPRA 与 IR 导入。
- DSP Scene 可按设备 ID、后端、声道布局、PCM/DSD 和采样率规则自动选择；它不是完整输出设备档案。
- WASAPI Shared/Exclusive、ASIO、CoreAudio Shared/Hog、ALSA、typed PCM passthrough。
- DSF、DFF、DoP、ASIO/ALSA Native DSD、SACD ISO、DST provider，以及 PCM→DSD64/128/256。
- PCM→PCM SRC/升频：输出级可锁定 44.1/48/88.2/96/176.4/192 kHz，支持 SWR 与构建可用时的 SoXR HQ/VHQ；启用后会正确关闭 bit-perfect 声明。
- DLNA/Chromecast 投送、局域网 Web 遥控、系统媒体控件、全局快捷键和托盘控制。
- 队列虚拟化、拖放排序、下一首播放、尾部追加、移除、清空和保存为歌单。

权威现状见[音频引擎架构](./twilight-audio-engine-architecture.md)、[音频引擎 API](./audio-engine-api.md)、[播放模式](./playback-modes.md)与[队列虚拟化](./playback-queue-virtualization.md)。

## 4. P0：发布与设备安全缺口

### PG-01 CUDA 加速并未实现

- **状态**：未实现
- **现状**：构建系统没有 CUDA language、CUDAToolkit、`.cu` 目标或 GPU runtime；PCM→DSD 使用 CPU 侧 `PcmToDsdModulator`。
- **缺口**：若产品文案声明“CUDA 加速”，会超过仓库实际能力。
- **建议范围**：先选择真正适合 GPU 的离线任务或大卷积，不把实时基础播放强制依赖 GPU；提供 CPU/GPU 一致性、自动回退、超时隔离和可量化基准。
- **验收**：能力查询明确报告 backend；无 NVIDIA GPU 时行为完全不变；GPU 异常不会中断播放；在公开 fixture 上证明收益后才进入 README。

### PG-02 真机音频证据未成为发布闭环

- **状态**：未验证
- **现状**：已经有 evidence runner，但 ASIO、WASAPI Exclusive、DoP DAC、Native DSD 和 SACD ISO 仍是 opt-in surface。
- **缺口**：默认测试可以证明逻辑正确，不能证明真实 DAC、驱动和 USB 链路长期稳定。
- **建议范围**：维护至少两类 WASAPI DAC、两类 ASIO 驱动、DoP、Native DSD 和 SACD ISO 的可追溯结果；记录设备、驱动版本、格式、缓冲、时长和 artifact。
- **验收**：发布候选的 `coverage.complete` 有对应 artifact；失败和未测项不能被手写状态绕过。

### PG-03 ASIO 驱动尚未进程级隔离

- **状态**：部分实现
- **现状**：已有独立音频服务、ASIO 控制线程、watchdog 与恢复诊断，但第三方 ASIO 驱动仍可拖垮承载它的音频服务。
- **缺口**：驱动卡死、COM 异常或缓冲回调破坏会扩大故障域。
- **建议范围**：增加 ASIO 专用 helper process，控制面和共享音频缓冲使用有界协议；进程退出时回收句柄并回退 WASAPI。
- **验收**：注入卡死、崩溃和超时后主应用仍响应；不会自动出声；用户可选择重新连接或回退。

### PG-04 ASIO 驱动 quirk 数据库缺失

- **状态**：未实现
- **现状**：已有 trace 与明确 failure reason，但没有按驱动/版本保存兼容策略。
- **缺口**：特殊 sample type、DSD buffer range、回调节奏和格式切换顺序只能依赖通用协商。
- **建议范围**：以驱动 CLSID、版本和能力指纹为键；只保存最小必要差异；所有 quirk 必须能禁用并出现在诊断报告中。
- **验收**：至少覆盖三个真实兼容性案例；未知驱动继续走通用路径；quirk 不得伪造设备能力。

### PG-05 DSD 自动降速率缺失

- **状态**：未实现
- **现状**：源 DSD 可按 Native→DoP→PCM 回退，PCM→DSD 支持 DSD64/128/256；没有 DSD512→256→128→64 的 DSD 域内降级。
- **缺口**：高倍率 DSD 在 DAC 不支持时会更早落到 PCM，不能优先保留 DSD 输出。
- **建议范围**：显式用户策略 `exact | downrate | pcm-fallback`；每次降级显示源倍率、实际倍率和原因。
- **验收**：不同设备能力矩阵下选择可预测；降级使用有效低通与噪声整形；从不把降级后的输出标成 source exact。

### PG-06 DSD/DoP 切换静音保护带缺失

- **状态**：未实现
- **现状**：DoP marker 相位和路由状态已经存在，但没有面向 DAC 失锁/重锁的可配置静音过渡。
- **缺口**：PCM、DoP、Native DSD 或不同倍率切换时，部分 DAC 可能产生爆音或短噪声。
- **建议范围**：设备级 pre-roll/post-roll 静音、DoP 合法静音帧、格式锁定确认和可诊断的过渡状态。
- **验收**：真机示波/录音证据没有非预期尖峰；过渡不污染曲目时间轴；gapless 状态诚实上报。

### PG-07 宣传能力与 runtime capability 缺少自动一致性检查

- **状态**：部分实现
- **现状**：引擎能报告能力，README 也注明多项限制，但没有测试阻止文案声明未编译或未验证的能力。
- **缺口**：CUDA、ASIO、VST3、SoXR、ebur128 等可选构建能力可能与发行包文案漂移。
- **建议范围**：从 staged release 读取 capability manifest，验证 README/发布说明中的受控能力表。
- **验收**：缺 helper、库或真实验证标志时，发布说明只能标为不可用、实验性或未验证。

## 5. P1：主力播放体验缺口

### PG-08 完整输出设备档案

- **状态**：部分实现
- **已有基础**：DSP Scene 已支持 `deviceIds`/`backends` 规则。
- **缺口**：设备匹配尚未把输出后端、设备、独占模式、缓冲、声道、音量安全、SRC、DSD 策略和 DSP Scene 作为一个原子档案管理。
- **建议范围**：为耳机、扬声器、USB DAC 建立档案；只在稳定设备 ID 匹配时自动应用；切换前展示会改变的输出链。
- **验收**：插拔设备后一次事务完成路由与 DSP 恢复；失败保持旧配置；不会短暂以错误音量输出。

### PG-09 异格式相邻曲目的连续播放策略

- **状态**：部分实现
- **现状**：同格式可 true gapless；`format_mismatch` 会阻断预加载提升。
- **缺口**：跨采样率、位深或声道布局的专辑不能同时获得统一体验。
- **建议范围**：提供 `bit-perfect 优先` 与 `专辑连续优先`；后者锁定输出格式并 SRC，前者允许设备重开并明确短间隔。
- **验收**：模式选择可预测；SRC 模式不误报 bit-perfect；切换策略写入诊断。

### PG-10 DSD 专辑 gapless

- **状态**：未实现
- **现状**：`dsd_path` 会阻断当前 gapless preload。
- **缺口**：连续 DSD 专辑仍需要重新建立路由或重新开流。
- **建议范围**：仅在相邻曲目 DSD transport、倍率、声道和设备格式完全一致时预载；任何不一致都保持阻断。
- **验收**：Native DSD 与 DoP 分别取得真机边界证据；marker 相位和静音过渡正确；失败不产生噪声。

### PG-11 交叉淡化策略仍较基础

- **状态**：部分实现
- **现状**：已有按秒 overlap mixing。
- **缺口**：没有曲线类型、按专辑/现场/CUE 自动禁用、短曲保护或基于响度的增益匹配策略。
- **建议范围**：线性/等功率曲线、元数据规则、最短剩余时长保护；BPM/乐句对齐属于后续实验项。
- **验收**：CUE pregap 和 gapless 专辑不会被错误覆盖；启用后稳定报告非 bit-perfect。

### PG-12 队列操作撤销与播放顺序历史

- **状态**：未实现
- **现状**：队列操作完整且支持保存，但没有面向用户的撤销栈和独立的实际播放顺序历史。
- **缺口**：误清空、误删除、随机模式回看和恢复刚才队列不够方便。
- **建议范围**：有界命令栈；记录稳定 `queueEntryId`；与最近播放统计分离。
- **验收**：20,000 项队列仍保持虚拟化预算；并发 revision 变化时撤销不会覆盖新队列。

### PG-13 通用智能随机

- **状态**：部分实现
- **现状**：已有稳定随机循环和网易云“心动模式”，但没有适用于本地及跨来源曲库的通用智能随机。
- **缺口**：不能按最近播放、艺人间隔、评分/收藏、重复录音和流派做可解释权重。
- **建议范围**：复用 logical track identity；算法输出原因；保留纯随机模式。
- **验收**：固定 seed 可复现；不会在大库热路径整表重建；同一录音不会因多来源被重复加权。

### PG-14 独立音高/调性控制

- **状态**：未实现
- **现状**：WSOLA 提供变速不变调，但没有在固定速度下移调，也没有 cents/半音控制。
- **缺口**：练习、扒谱和卡拉 OK 场景不足。
- **建议范围**：独立 tempo 与 pitch；限制安全范围；与 A-B 循环联动。
- **验收**：参数变化连续无爆音；非 1.0/0 semitone 时明确非 bit-perfect；CPU 超载时可回退。

### PG-15 ReplayGain/R128 批量生成与写回

- **状态**：部分实现
- **现状**：能读取 Track/Album 标签，也能为 Loudnorm 离线测量和缓存；没有面向媒体库的 ReplayGain/R128 批量计算、专辑分组和受控写回。
- **缺口**：无标签曲库只能依赖 fallback 或播放器私有缓存，无法生成可移植标签。
- **建议范围**：先提供 sidecar/库数据库结果，再提供显式文件写回；写回必须复用标签事务、备份与格式白名单。
- **验收**：Track/Album 结果可重复；取消不会留下半套专辑标签；只在用户明确授权时修改音频文件。

### PG-16 章节解析与导航

- **状态**：未实现
- **现状**：已有书签、长音频续播和播客进度，但没有 MP4/Matroska/ID3/Podcast chapter 的统一模型。
- **缺口**：播客、有声书、现场录音无法按章节浏览、跳转和显示标题。
- **建议范围**：共享 `MediaChapter` 类型；本地 metadata、CUE 与 provider 章节统一为只读时间段；书签继续作为用户数据存在。
- **验收**：章节时间严格递增且受 duration 限制；seek 仍走现有 preload/播放时钟契约。

### PG-17 智能静音与片头片尾规则

- **状态**：未实现
- **现状**：播客已有单集进度和记忆倍速。
- **缺口**：没有静音压缩、每节目跳过片头/片尾和“睡眠后回退几秒”。
- **建议范围**：默认关闭；静音检测运行在播放或预分析的有界路径；每个节目保存规则；不能用于音乐默认播放。
- **验收**：不会跳过低动态音乐或有声内容中的有意停顿；所有自动 seek 在 UI 可见且可撤销。

### PG-18 播客离线下载与保留策略

- **状态**：未实现
- **现状**：播客 enclosure 以网络流播放；provider 下载管理器不等于播客离线库。
- **缺口**：缺少按集下载、自动下载新集、已播清理、校验和断点续传。
- **建议范围**：复用 cache/download 安全边界，但使用独立的播客保留策略和来源身份。
- **验收**：离线时可恢复播放与章节/进度；feed URL 变化不产生重复文件；删除行为明确可恢复性。

### PG-19 远程控制能力不完整

- **状态**：部分实现
- **现状**：Web 遥控支持播放、暂停、前后曲、seek、音量和跳转队列索引。
- **缺口**：不能搜索/浏览媒体库、添加/删除/排序队列、切换播放模式、查看输出诊断或管理投送队列。
- **建议范围**：先补只读浏览与受 revision 保护的队列命令；音频后端/DSP 等高风险设置不默认开放。
- **验收**：所有写命令复用主播放器的稳定身份与 revision；PIN/token 限速和局域网边界保持不变。

### PG-20 无缝输出设备切换

- **状态**：部分实现
- **现状**：已有设备热插拔刷新、route restore 和失败回退；切换后仍可能需要重开后端/流。
- **缺口**：同一后端内换设备或 shared/exclusive 切换没有统一的短静音、位置保持和可回滚事务体验。
- **建议范围**：保存播放位置和时钟 generation；先验证目标、再切换；失败继续旧设备或停在明确状态。
- **验收**：不会双设备同时出声；不会恢复到错误位置；DSD/PCM 切换遵循 PG-06。

## 6. P2：生态与进阶能力

### PG-21 AirPlay/RAOP 输出

- **状态**：未实现
- **现状**：已有 DLNA 和 Chromecast；设计文档提到 AirPlay，但没有协议运行路径。
- **建议范围**：优先使用系统 picker 或成熟、许可证兼容的实现；明确 AirPlay 1/2、加密和同步能力边界。
- **验收**：发现、连接、seek、音量、断线恢复和媒体 URL 授权均有测试；不把普通 AirPlay 投送描述成 bit-perfect 本机输出。

### PG-22 多房间/多设备同步

- **状态**：未实现
- **现状**：文档明确“不包含高级多设备同步”。
- **建议范围**：主时钟、每设备延迟估计、漂移校正、分组音量和成员掉线策略；不能用简单同时发起播放冒充同步。
- **验收**：长时间漂移和房间间偏差有量化指标；成员变化不会打断未变化设备。

### PG-23 HDMI 编码音频直通

- **状态**：未实现
- **现状**：当前 passthrough 指 typed PCM 或 DSD transport，不是 IEC 61937 Dolby/DTS bitstream。
- **建议范围**：仅在合法、无需解码授权且设备声明支持时提供 AC-3/E-AC-3/DTS 等封装直通；与软件音量/DSP 明确互斥。
- **验收**：状态页明确区分 PCM、DSD 和 encoded bitstream；错误格式不会以噪声送往 PCM 设备。

### PG-24 自动房间测量与扬声器校准向导

- **状态**：未实现
- **现状**：能够导入 REW/EQ APO/IR，并有 5.1/7.1 场景模板；没有麦克风采集、扫频、延迟/电平测量和自动滤波器生成。
- **建议范围**：如果实现，必须独立于实时播放 RPC；提供麦克风选择、测试音安全音量、测量质量检查和人工确认。
- **验收**：不会未经确认播放测试音；生成结果可导出并作为普通 DSP asset 使用；失败不改当前场景。

### PG-25 蓝牙输出可观测性

- **状态**：未实现
- **现状**：蓝牙设备可通过系统输出出现，但播放器不报告协商 codec、采样率、系统处理或链路变化。
- **建议范围**：只做平台允许的只读诊断；不绕过系统蓝牙栈。
- **验收**：未知信息显示“系统未提供”，不根据设备名猜测 aptX/LDAC/AAC。

### PG-26 音频 CD 播放与抓轨

- **状态**：未实现
- **建议范围**：这是独立产品面；需要 CDDA、偏移校正、Secure Rip、校验数据库、元数据和错误恢复。除非用户群明确需要，否则不应挤占输出可靠性工作。
- **验收**：播放和抓轨分离；抓轨结果带可复核错误报告；不伪造 AccurateRip 类验证。

### PG-27 Scrobbling 生态

- **状态**：可选扩展
- **现状**：插件计划包含 scrobbler 示例，但核心没有 Last.fm/ListenBrainz 成品集成。
- **建议范围**：优先作为插件，消费版本化播放事件；支持隐私开关、离线队列和去重。
- **验收**：禁用后不联网；短播、seek、重复和离线重传符合目标服务规则。

### PG-28 小众格式与物理介质扩展

- **状态**：可选扩展
- **现状**：已覆盖主流 PCM、无损、DSD、CUE 和 SACD ISO；扫描白名单没有穷尽 FFmpeg 可解码的所有格式。
- **候选**：TAK、TTA、Musepack、WSD，以及确有用户需求时的 DVD-A/BD Audio。
- **验收**：先扩展 fixture、metadata、seek、duration 和扫描策略，再添加后缀；“FFmpeg 能打开”不等于产品级支持。

### PG-29 完整 SDM 升频体系

- **状态**：部分实现
- **已经实现**：PCM→PCM SRC/升频已有输出采样率锁、SWR/SoXR 质量档位、dither、运行状态与 UI；CPU 侧 `PcmToDsdModulator` 已用半带插值和五阶 sigma-delta 将 PCM 转为 DSD64/128/256，并可通过 Native DSD 或 DoP 输出。
- **尚未实现**：DSD/SDM→更高倍率 SDM 的重采样与再调制、DSD512、可选择的插值滤波器与调制器、不同内容/设备的调制策略、GPU 后端，以及发布级真机和客观质量证据。
- **产品边界**：现状可以描述为“PCM SRC”与“实验性 PCM→DSD64/128/256”，不能笼统宣传为 HQPlayer 类“高品质 SDM 升频”或“CUDA SDM”。SDM 与 DSD 在这里指同一类 1-bit sigma-delta 数据域，但文案应展示输入域、处理方式和实际输出倍率。
- **建议范围**：先建立 PCM→PCM、PCM→SDM、SDM→SDM 三条独立能力模型；为插值滤波器、noise-transfer function、headroom、稳定性重置和目标倍率建立可选配置；最后再评估 SIMD/GPU，而不是让 CUDA 成为功能成立的前提。
- **验收**：状态页明确显示 `PCM→PCM`、`PCM→SDM` 或 `SDM→SDM`；覆盖 44.1 kHz 与 48 kHz 家族；具备带内频响、阻带、噪声谱、互调、稳定性、CPU deadline 和真机 DAC 锁定证据；任何转换都不得报告 source exact 或 bit-perfect。

## 7. 不应登记为缺口的项目

### 7.1 WASAPI Native DSD 与 CoreAudio Native DSD

WASAPI 和 CoreAudio 没有本项目可利用的通用 Native DSD 通道。正确路径是 WASAPI/CoreAudio Exclusive 上的 DoP，或 PCM fallback；这属于平台限制。

### 7.2 DSP 开启时仍要求 bit-perfect

ReplayGain、EQ、卷积、Crossfeed、SRC、倍速、软件音量和绝大多数声道处理都会改变样本。此时报告 `outputPerfect=false` 是正确行为。

### 7.3 WASAPI Shared 要求 bit-perfect

Shared 路径经过系统 mixer，不能承诺播放器到设备逐位不变。应继续提供真实链路诊断，而不是放宽 evaluator。

### 7.4 MQA unfold/认证

当前 `.mqa` 只按兼容容器处理。没有合法授权和可验证实现时，不应声称 unfold、render 或认证。

### 7.5 崩溃后自动续播

当前恢复配置和队列、但等待用户确认继续播放，是避免意外出声的安全设计，不是缺陷。

### 7.6 把所有投送都称为无损或 bit-perfect

DLNA、Chromecast、未来 AirPlay 的实际格式由接收端、协议和媒体 URL 决定，不能复用本机 `outputPerfect` 结论。

## 8. 推荐实施顺序

面向其他 Agent 的逐项工作包、阶段门禁、冲突矩阵和 Evidence 回填格式见 [`plans/022-playback-capability-gap-execution-checklist.md`](../plans/022-playback-capability-gap-execution-checklist.md)。

### M1：宣传与证据收口

包含 PG-01、PG-02、PG-07。

- 删除或降级没有 runtime 事实支持的能力声明。
- 固化真实设备 artifact 与发布能力 manifest。
- 不改变播放行为，先建立可信基线。

### M2：设备安全与 DSD 切换

包含 PG-03、PG-04、PG-05、PG-06、PG-20。

- ASIO 故障域隔离。
- DSD 域内降级和静音过渡。
- 输出切换使用可回滚事务。

### M3：设备自动化与连续播放

包含 PG-08、PG-09、PG-10、PG-11、PG-15。

- 完整设备档案。
- 异格式与 DSD 专辑连续策略。
- 响度标签生成和更可控的 crossfade。

### M4：长音频与远程体验

包含 PG-12 至 PG-19。

- 队列撤销、智能随机、章节、智能静音和播客离线。
- 扩展 Web 遥控时继续遵守现有授权和 revision 边界。

### M5：生态扩展

包含 PG-21 至 PG-29，按真实用户需求单独立项，不作为主播放器可靠性门槛。

## 9. 验证矩阵

每项实现除自己的单元测试外，至少追加以下现有 gate：

| 变更面                       | 最小现有 gate                                                          |
| ---------------------------- | ---------------------------------------------------------------------- |
| 队列、播放模式、书签、长音频 | `pnpm run test:playback-routing`、`pnpm run test:queue-virtualization` |
| 睡眠、智能静音               | `pnpm run test:sleep-timer`、`pnpm run test:playback-routing`          |
| DSP、SRC、响度、校正         | `pnpm run test:dsp-graph`、`pnpm run test:audio-manager`               |
| 音频 IPC、输出恢复           | `pnpm run test:audio-manager`、`pnpm run typecheck`                    |
| 原生输出、DSD、ASIO          | `pnpm run test:audio-engine:mingw` 加对应 opt-in 真机 smoke            |
| 投送、AirPlay、多房间、远程  | `pnpm run test:radio-remote`                                           |
| 播客和网络缓存               | `pnpm run test:radio-remote`、`pnpm run test:network-sources`          |
| 发布能力声明                 | `pnpm run test:no-real-device` 加 staged artifact capability 检查      |

提交前仍需运行 `pnpm run lint`、`pnpm run typecheck` 和 `pnpm run format`。真实设备能力不得用 mock 结果替代。

## 10. 维护规则

- 功能落地后，把对应条目改为“已闭环”并迁入相关权威契约，不在本文长期保留已经完成的路线图细节。
- 新增缺口必须同时写明现状证据、用户价值、建议边界和可证伪验收标准。
- “未搜索到字符串”只能作为线索；最终状态必须结合公共类型、main/preload/renderer 路径、native 实现、测试和产品入口判断。
- 不把受平台限制、会破坏产品安全边界或仅靠营销命名成立的项目登记为工程缺陷。
